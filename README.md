# DepositProj

**Прогнозирование вероятности открытия банковского депозита с помощью машинного обучения.**

DepositProj — учебный исследовательский проект, объединяющий эксперименты с моделями для табличных данных и веб-приложение на Streamlit. По характеристикам клиента и истории маркетинговых контактов система оценивает вероятность подписания договора на открытие депозита.

В приложении используется стекинг: прогнозы TabM, CatBoost и LightGBM объединяет логистическая регрессия. Для анализа отдельных прогнозов доступны объяснения SHAP.

## Возможности

- **Одиночный прогноз:** ввод параметров клиента через форму, оценка вероятности и вывод результата классификации.
- **Пакетный прогноз:** загрузка CSV, обработка нескольких клиентов и скачивание результатов в `prediction_results.csv`.
- **Интерпретация:** SHAP force plots для пяти моделей CatBoost после одиночного прогноза.
- **Обучение ансамбля:** стратифицированная кросс-валидация на пяти фолдах и обучение метамодели на out-of-fold прогнозах.
- **Исследование признаков:** создание новых признаков, target encoding, count encoding и отбор с помощью BorutaShap.
- **Эксперименты:** подбор гиперпараметров через Optuna, сравнение моделей, анализ ROC-AUC и матриц ошибок.

## Как устроен прогноз

```text
Данные клиента: 16 исходных признаков
                  ↓
Создание признаков и предобработка
                  ↓
     TabM       CatBoost      LightGBM
   5 моделей    5 моделей     5 моделей
       ↓            ↓            ↓
  Усреднение прогнозов внутри каждого семейства
                  ↓
      Логистическая регрессия
                  ↓
  Вероятность открытия депозита и класс
```

Всего приложение загружает 15 базовых моделей и одну метамодель. Сохранённые модели в репозитории относятся к эксперименту `iteration_14`.

В обоих режимах класс `1` присваивается при вероятности **≥ 0,37**.

## Быстрый старт

Для локального окружения можно использовать **Python 3.11**. Зависимости перечислены в `requirements.txt`; совместимость конкретного окружения необходимо проверить при установке.

### 1. Склонируйте репозиторий

```bash
git clone https://github.com/MarkSkryabin/DepositProj.git
cd DepositProj
```

Репозиторий содержит CSV-данные, обученные модели и результаты экспериментов, поэтому загрузка может занять некоторое время.

### 2. Создайте виртуальное окружение

```bash
python -m venv .venv
```

Активация в Windows PowerShell:

```powershell
.\.venv\Scripts\Activate.ps1
```

Активация в Linux / macOS:

```bash
source .venv/bin/activate
```

### 3. Установите зависимости

```bash
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
```

### 4. Проверьте настройки

В корне проекта должен находиться файл `.env`:

```dotenv
NAME=iteration_14
INFERENCE_MODEL=iteration_14
```

- `NAME` — имя эксперимента, используемое скриптами обучения и сохранения результатов.
- `INFERENCE_MODEL` — часть имени файлов базовых моделей, загружаемых приложением.

Для запуска с готовыми моделями оставьте `INFERENCE_MODEL=iteration_14`. Приложению нужны:

```text
models/TabM_iteration_14_fold_1.pkl … fold_5.pkl
models/CatBoost_iteration_14_fold_1.pkl … fold_5.pkl
models/LightGBM_iteration_14_fold_1.pkl … fold_5.pkl
models/meta_model_logistic_regression.pkl
```

Также сохраните в корне `train.csv`, `confirmed_features.txt` и `image.svg`. Обучающая выборка нужна даже для готового приложения: функция `preprocessing()` использует её для вычисления target encoding.

### 5. Запустите приложение

Выполняйте команду из корня репозитория, поскольку пути к данным и моделям относительные:

```bash
python -m streamlit run app.py
```

Откройте адрес, который Streamlit выведет в терминале, обычно [http://localhost:8501](http://localhost:8501).

TabM загружается на CPU: на CPU переносятся как сохранённые тензоры, так и устройство внутри обученного интерфейса pytabkit. Для работы с готовыми моделями повторное обучение не требуется.

## Использование

### Одиночный прогноз

1. Откройте вкладку **«Одиночный прогноз»**.
2. Заполните характеристики клиента и параметры маркетингового контакта.
3. Нажмите **«Сделать прогноз»**.
4. Перейдите во вкладку **«Аналитика»**, чтобы посмотреть вклад признаков в прогнозы CatBoost.

SHAP-графики создаются в памяти и хранятся только в текущем сеансе пользователя. Вкладка аналитики показывает объяснения последнего одиночного прогноза этого сеанса; до первого прогноза отображается подсказка. Старые HTML-файлы из репозитория приложение не использует.

### Пакетный прогноз

Во вкладке **«Множественный прогноз»** загрузите CSV с заголовком и разделителем-запятой. Используйте исходные признаки; дополнительные признаки приложение создаёт самостоятельно. Категориальные значения должны быть записаны на английском языке, как в обучающих данных.

| Признак | Описание / значения |
| --- | --- |
| `age` | Возраст клиента |
| `job` | `admin.`, `blue-collar`, `entrepreneur`, `housemaid`, `management`, `retired`, `self-employed`, `services`, `student`, `technician`, `unemployed`, `unknown` |
| `marital` | `single`, `married`, `divorced` |
| `education` | `primary`, `secondary`, `tertiary`, `unknown` |
| `default` | Просрочка по кредиту: `yes` / `no` |
| `balance` | Среднегодовой баланс в евро |
| `housing` | Жилищный кредит: `yes` / `no` |
| `loan` | Потребительский кредит: `yes` / `no` |
| `contact` | `cellular`, `telephone`, `unknown` |
| `day` | День месяца последнего контакта |
| `month` | `jan`, `feb`, `mar`, `apr`, `may`, `jun`, `jul`, `aug`, `sep`, `oct`, `nov`, `dec` |
| `duration` | Длительность последнего контакта в секундах |
| `campaign` | Количество контактов в текущей кампании |
| `pdays` | Дни после предыдущего контакта; `-1` — контакта ранее не было |
| `previous` | Количество контактов до текущей кампании |
| `poutcome` | `success`, `failure`, `other`, `unknown` |

Пример входного файла:

```csv
age,job,marital,education,default,balance,housing,loan,contact,day,month,duration,campaign,pdays,previous,poutcome
35,technician,married,tertiary,no,1500,yes,no,cellular,15,may,240,2,-1,0,unknown
58,retired,married,secondary,no,3200,no,no,telephone,10,jun,420,1,180,2,success
```

В интерфейсе отображаются `probability` — вероятность положительного класса — и `result` — класс `0` или `1`. Кнопка **«Скачать результаты CSV»** сохраняет обработанные признаки и прогнозы в `prediction_results.csv` с кодировкой UTF-8 BOM. Результаты не записываются в общий файл на сервере.

## Данные

| Файл | Назначение |
| --- | --- |
| `train.csv` | Обучающая выборка с целевым столбцом `y` и идентификатором `id` |
| `test.csv` | Данные для получения прогнозов без целевого столбца |
| `sample_submission.csv` | Шаблон файла предсказаний |
| `bank-full.csv` | Дополнительный набор банковских данных; читается с разделителем `;` |
| `train_pseudo.csv` | Псевдоразмеченные данные для экспериментов |

Целевая переменная `y`: **1 — клиент открыл депозит, 0 — не открыл**. Файлы submission содержат `id` и `y`, где `y` — предсказанная вероятность положительного класса.

## Обучение и эксперименты

Основной скрипт ансамбля:

```bash
python train_ansamble.py
```

Он создаёт признаки, выполняет пятифолдовую `StratifiedKFold`-валидацию, обучает TabM, CatBoost и LightGBM, сохраняет модели и формирует прогнозы. Затем логистическая регрессия обучается на трёх столбцах OOF-вероятностей. Основная метрика — ROC-AUC; дополнительно выводится отчёт классификации и сохраняются графики.

Перед запуском учитывайте настройки текущего кода:

- В `get_best_params()` заданы GPU-настройки для CatBoost и LightGBM и `cuda` для TabM. Для обучения на CPU параметры нужно изменить в `train_functions.py`.
- Скрипт читает `train_pseudo.csv`, даже когда добавление псевдоразмеченных данных отключено через `add=False`.
- Метамодель сохраняется в корень как `meta_model_logistic_regression.pkl`, а приложение читает её из `models/`. После обучения скопируйте новый файл в `models/` и согласуйте `INFERENCE_MODEL` с `NAME` обученного эксперимента.
- Вывод `ФИНАЛЬНЫЙ META-AUC` вычисляется на тех же OOF-строках, на которых обучена метамодель. Для независимой оценки всего стекинга нужна отдельная проверочная выборка или дополнительный уровень валидации.

Другие исследовательские скрипты:

| Файл | Назначение |
| --- | --- |
| `train_model.py` | Обучение отдельной модели CatBoost |
| `cross_validation.py` | Эксперименты с кросс-валидацией |
| `create_submission.py` | Прогнозы CatBoost и эксперименты с псевдоразметкой |
| `feature_scoring.py` | Отбор признаков через BorutaShap |
| `optuna_optimization.py`, `hyperparameters_optim.py` | Подбор гиперпараметров |
| `correlation.py` | Анализ корреляций |
| `shap_file.py`, `shap_file_stremlit.py` | Подготовка SHAP-визуализаций |

Исследовательские скрипты содержат настройки отдельных экспериментов и могут требовать согласования параметров и вызовов функций перед запуском.

## Особенности текущей реализации

- Признак `duration` известен после завершения контакта. Это следует учитывать, если модель применяется для отбора клиентов до звонка.
- Частотные и групповые признаки вычисляются по переданному набору данных, поэтому прогноз для клиента может зависеть от состава загруженного CSV и отличаться от одиночного прогноза.

## Проверка исправлений приложения

Исходники приложения сохранены в UTF-8. Список профессий формируется из словаря, чтобы подписи формы и значения модели не расходились. Для каждого семейства моделей создаётся отдельная копия входных данных: преобразование категорий для LightGBM не меняет данные CatBoost и SHAP. HTML-графики SHAP формируются в памяти, без зависимости от системной кодировки Windows.

В окружении с установленными зависимостями:

```bash
python -m pip install pytest
python -m pytest -q
```

Проверки включают одиночный прогноз на сохранённых моделях, выбор профессии «менеджер / руководитель», переход в аналитику и создание SHAP-графиков при кодировке Windows cp1251.
